
## Pre-analysis for US-072 (Gemini 2.5 Pro)
This user story describes a booking cancellation workflow for a TypeScript/Node.js application, not a Frappe/Python app. The file paths (`.ts`, `.json`) and logic are specific to that environment.

Here is the technical brief based on the provided JSON for the actual TypeScript project:

**Project:** TypeScript/Node.js Booking Assistant

**1. Files to Modify:**
*   `src/assistant/data/workflows.json`: To define the new cancellation workflow steps.
*   `src/tools/booking-tools.ts`: To implement the core credit calculation logic.
*   A test file (e.g., `src/tools/booking-tools.test.ts`): To add unit tests verifying the credit calculation.

**2. Key Entities Involved:**
*   **Workflow Step:** A new step named `process_booking_cancellation` is required.
*   **Tool Function:** A new function within `booking-tools.ts` will calculate the credit based on booking data.
*   **Booking Object:** The function will need access to the booking's check-in timestamp.

**3. Implementation Approach:**
1.  In `src/assistant/data/workflows.json`, add a `process_booking_cancellation` workflow. It should prompt the user for confirmation and then call the credit calculation tool.
2.  In `src/tools/booking-tools.ts`, create a function `calculateCancellationCredit(booking)`.
3.  This function will calculate the hours between `now` and the `booking.checkInDate`.
4.  Use an if/else statement: if hours > 48, return a "100% credit" message; otherwise, return a "50% credit" message.
5.  Add unit tests to validate both the >48h and <48h scenarios.

**4. Edge Cases & Gotchas:**
*   **Timezones:** Ensure the current time and check-in time are compared in the same timezone (preferably UTC) to prevent miscalculations.
*   **Booking Status:** The workflow should verify the booking is in a cancellable state before proceeding.
*   **Input Validation:** The check-in date from the booking object must be a valid and parsable date.

### **Technical Brief: US-072 Booking Cancellation Workflow**

**Target App:** `lhdn_payroll_integration`

**1. Python Files to Modify:**
*   `lhdn_payroll_integration/doctype/booking/booking.py`: This controller file will house the primary logic for credit calculation. A new method like `_calculate_cancellation_credit` should be added here.
*   `lhdn_payroll_integration/hooks.py`: To trigger the cancellation logic on a document event.

**2. Frappe DocTypes & Hooks:**
*   **DocTypes:**
    *   `Booking`: This DocType needs a `status` field (e.g., 'Confirmed', 'Cancelled') and a `check_in_date` (Datetime). The cancellation logic will be triggered by a state change on this document.
    *   `Journal Entry` or `Sales Credit Note`: A new `Journal Entry` should be created programmatically to credit the guest's account upon cancellation.
*   **Hooks:**
    *   `on_cancel` or `on_update`: In `hooks.py`, use the `on_cancel` hook for the `Booking` DocType to call your new Python method. This is the standard trigger for cancellation logic.

**3. Recommended Implementation Approach:**
1.  In `hooks.py`, hook the `on_cancel` event for the `Booking` DocType to a new method in `booking.py`.
2.  In `booking.py`, the method will compare the `check_in_date` with the current datetime.
3.  Based on the >48h or <48h rule, calculate the 50% or 100% credit amount from the booking's `grand_total`.
4.  Use `frappe.new_doc('Journal Entry')` to create and submit a new JE, crediting the appropriate guest/receivables account.

**4. Edge Cases & Gotchas:**
*   **Logical App Placement:** This booking functionality is a poor fit for a payroll app. It should ideally be in a dedicated hospitality or bookings app.
*   **Timezones:** Ensure all date comparisons (`check_in_date` vs `now`) are timezone-aware to prevent incorrect credit calculations.
*   **Idempotency:** The logic must prevent issuing credit more than once for the same cancellation. Check if a credit-related `Journal Entry` already exists for the cancelled booking before creating a new one.


## Iteration - Story: US-072 - Add booking cancellation workflow with automatic guest credit calculation

### What was implemented
1. **Credit calculation function** in `src/tools/bookings.ts`:
   - `calculateCancellationCredit(checkInDate)` function calculates refund percentage based on hours until check-in
   - Returns "100% credit applied" if cancellation is >48 hours before check-in
   - Returns "50% credit applied" if cancellation is ≤48 hours before check-in
   - Handles ISO date strings and Date objects, with graceful error handling

2. **Booking cancellation workflow** in `src/assistant/data/workflows.json`:
   - New workflow ID: `booking_cancellation`
   - Workflow nodes:
     - `cancel_intro`: Introduction message
     - `ask_checkin_date`: Collects check-in date from guest
     - `confirm_cancellation`: Asks for confirmation
     - `calculate_credit`: Displays credit tier information
     - `notify_staff`: Forwards cancellation request to staff via WhatsApp
   - Supports English, Malay, and Chinese

3. **Routing entry** in `src/assistant/data/routing.json`:
   - New intent: `booking_cancellation` -> workflow `booking_cancellation`

4. **Unit tests** in `src/tools/bookings.test.ts`:
   - 9 comprehensive tests covering:
     - 72-hour cancellation returns 100% credit ✅
     - 24-hour cancellation returns 50% credit ✅
     - Boundary conditions (exactly 48 hours) ✅
     - Date string and Date object handling ✅
     - Invalid date error handling ✅
     - Refund timeline inclusion ✅
     - Past date handling ✅
   - All tests passing (9/9)
