### Technical Brief: Intent Classification Semantic Cache (US-575)

**Objective:** Implement an embedding-based semantic cache using Redis to intercept and return pre-classified intents for similar user messages, bypassing redundant AI calls.

**1. File Modifications:**

*   **Create:** `lhdn_payroll_integration/utils/similarity_cache.py`
    *   This new file will contain a `SimilarityCache` class responsible for all Redis interactions (storing and retrieving cached `(embedding, intent, confidence)` tuples). It will handle the logic for calculating cosine similarity.
*   **Modify:** `lhdn_payroll_integration/api/process_message.py` (or similar existing API endpoint)
    *   This is the likely entry point where user messages are received. It needs to be modified to consult the `SimilarityCache` *before* making a call to the external AI for intent classification.

**2. Frappe Hooks & DocTypes:**

*   **Hook:** The logic will be triggered within a whitelisted API method (`@frappe.whitelist()`) that handles incoming messages, rather than a document hook.
*   **DocTypes:** No specific DocType modifications are required. The cache will operate on raw message text and user context before any documents are necessarily created. It will use the `User`'s ID (`frappe.session.user`) for profile-specific caching.

**3. Implementation Approach:**

1.  In `similarity_cache.py`, create a `SimilarityCache` class.
2.  Implement a `lookup(text_embedding)` method that fetches all cached embeddings for the current user from Redis (`frappe.cache()`). It will iterate through them, calculate the cosine distance, and return the cached intent data if the similarity score is > 0.95.
3.  Implement a `store(embedding, intent, confidence)` method to save the new classification result to Redis with a 4-hour TTL (`expires_in_seconds=14400`).
4.  In the main API endpoint, before calling the AI, generate an embedding for the incoming message.
5.  Call the `SimilarityCache.lookup()` method. If it returns a cached intent, return that intent immediately.
6.  If no cache hit, proceed with the AI call. On successful classification, use `SimilarityCache.store()` to cache the new result.

**4. Edge Cases & Gotchas:**

*   **Performance:** Iterating and calculating similarity against a large number of cached embeddings for a single user could be slow. The number of cached items per user should be capped (e.g., last 50).
*   **Cache Keying:** Use a structured, user-specific key like `intent_cache:{user_id}:{message_hash}` to ensure profile isolation.
*   **Empty/Short Messages:** The system should bypass caching for very short or empty messages where semantic meaning is ambiguous.
*   **Embedding Model Versioning:** Ensure the same embedding model is used for both the cached embeddings and incoming messages. A mismatch will make similarity scores meaningless.

## Iteration [110] - Story: US-579 - Add Custom Fallback Prompts for Low-Confidence Intent Classifications

### What was implemented
- Created `src/assistant/fallback-prompt-selector.ts` with getFallbackPrompt(), hasIntentFallbackPrompt(), and invalidateFallbackPromptCache()
  - Loads intent definitions with fallbackPrompt field from intent-keywords.json
  - Returns multilingual fallback prompts (en, ms, zh, ta)
  - Falls back to English if language not available
  - Caches prompts in memory for performance
- Updated `src/assistant/data/intent-keywords.json` with fallbackPrompt field for 10 key intents:
  - booking, checkin_info, checkout_info, wifi, payment, pricing, complaint, contact_staff, availability, facilities_info, rules_policy
  - Each fallback prompt is context-specific and multilingual (English, Malay, Chinese, Tamil)

  - All tests passing

### Patterns discovered
- Fallback prompts follow same structure as knowledge.json responses (multilingual objects)
- Intent-specific prompts provide better UX than generic "I didn't understand" message
- Can optionally add fallback prompts to additional intents without breaking backward compatibility (intents without fallback return null)
- Caching improves performance: file loaded once into memory, reused for all calls

### Gotchas
- Project is ES module based; had to use .cjs extension for Node script to use require()
- Fallback prompts are optional per intent — intents without fallback simply return null
- Test had to check for Malay text ("petang") rather than English word "Malay" to verify language
