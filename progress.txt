
## Pre-analysis for US-213 (Gemini 2.5 Pro)
Based on the user story and project structure, this is a **NodeJS/TypeScript** task, not Frappe/Python. The following brief is tailored for a TypeScript developer.

**Technical Brief: US-213 Intent Keyword Suggestion Engine**

1.  **Files to Create/Modify:**
    *   **Primary Logic:** Create a new file `scripts/suggest-keywords.ts`. This will house the main logic for the CLI command and data analysis.
    *   **Configuration:** Modify `package.json` in the `scripts` section to add `"suggest:keywords": "ts-node scripts/suggest-keywords.ts"`.
    *   **Validation:** Create `src/schemas/keyword-suggestion.schema.json` to validate the final JSON output.
    *   **Testing:** Create `tests/suggest-keywords.test.ts` to test the keyword extraction logic and output schema.

2.  **Involved Modules & Data Structures:**
    *   **Database:** The script must query the `escalation_queue` table. Use the existing Drizzle ORM setup (inferred from `drizzle.config.ts`) for database access.
    *   **Intent Profiles:** Read intent definitions and existing keywords, likely from files validated by `scripts/validate-intent-profile.ts`.

3.  **Recommended Implementation Approach:**
    *   Use a library like `commander` or `yargs` in `suggest-keywords.ts` to parse CLI arguments (`--profile`, `--days`).
    *   Fetch misclassified messages from the `escalation_queue` table for the specified period.
    *   Group messages by `intent_id`. For each group, use a TF-IDF library (e.g., `natural`) to process the message text and identify 2-3 terms with the highest scores.
    *   Filter out common English "stop words" (e.g., "the", "a", "is") to ensure suggestions are meaningful.
    *   Generate a JSON object matching the acceptance criteria and validate it against the schema before printing to `stdout`.

4.  **Edge Cases & Gotchas:**
    *   The `estimated_accuracy_boost_percent` is non-trivial to calculate. For the initial implementation, return `0` or `null` as a placeholder.
    *   The script must handle intents with no recent escalations gracefully.
    *   Ensure the database query is performant to avoid timeouts on large `escalation_queue` tables.
    *   Tokenization for TF-IDF should handle punctuation and case consistently to produce clean keywords.
