### Patterns discovered
- FuzzyIntentMatcher (Fuse.js) works best with SHORT queries (≤5 words) that closely match keyword entries
- Long natural-language queries ("I want to book a room tonight") return NO MATCH because Fuse.js does fuzzy matching with the query as search term against keyword strings — long queries fail when they're longer than keywords
- Substring fallback only triggers for keywords with 4+ words AND 18+ chars
- Solution: regression test samples should be drawn directly from or near actual keyword entries
- The substring match approach: user message must CONTAIN the keyword, not the other way around

### Gotchas
- Fuse.js threshold=0.3 means 0=exact, 1=anything; distance=100; ignoreLocation=true
- When query length > keyword length, Fuse returns no results — not a bug, just the matching direction
- Malay keywords: "tempahan"=booking, "nak book"=booking, "ada bilik"=availability — all in keywords.json
