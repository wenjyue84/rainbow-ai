- Created `src/lib/pci-header-tamper-detection.ts`: Express middleware that intercepts res.end on payment-adjacent routes, reads outgoing headers after Helmet, normalizes CSP (strips per-request nonces), detects drift against baseline, logs structured diff, and fires admin alert (throttled per path)
- Added `notifyAdminHeaderTamper` to `src/lib/admin-notifier.ts`: WhatsApp alert with diff details, PCI reference, and remediation steps
- Wired `setPciHeaderAlertFn` in `src/lib/baileys-supervisor.ts` after `initAdminNotifier` so the alert function is available once WhatsApp is ready

- Added `pci:header-scan` npm script
### Patterns discovered
- CSP nonce is per-request (randomBytes(16)) — normalize by replacing `'nonce-...'` → `'nonce-DYNAMIC'` before diff
- res.end() interception is the correct post-Helmet hook (res.on('finish') fires too late to read headers reliably)
- HSTS check is skip-in-development (Helmet disables it when NODE_ENV != 'production')
- Alert fn is initialized lazily via setPciHeaderAlertFn to avoid circular dep between admin-notifier and pci-header-tamper-detection

## Iteration 4 - Story: US-1040 - PCI DSS 4.0 Req 6.4.3: webchat payment page script inventory and SRI enforcement
### What was implemented
- Created `src/public/pci-script-inventory.json`: Version-controlled script inventory documenting every script on payment-adjacent webchat pages with justification, protection mechanism, reviewer, and dates
- Created `scripts/validate-sri.mjs`: Build-time SRI validation that scans payment-adjacent HTML for third-party `<script src>` tags and fails the build if any lack integrity/crossorigin attributes or are not in the inventory
- Created `scripts/pci-quarterly-scan.mjs`: Quarterly drift scan that generates a JSON compliance report comparing current HTML state against the approved inventory baseline
- Added `pci:scan` npm script for on-demand quarterly reporting
- Wired `validate-sri.mjs` into `npm run build` pipeline (runs before esbuild)
- Enhanced `/webchat.html` CSP: added `default-src 'self'; script-src 'self' 'unsafe-inline'; connect-src 'self'` (previously only had frame-ancestors)
- Fixed `/chat/:profileId` nonce injection: main webchat IIFE now gets CSP nonce attribute (was missing, would be blocked by Helmet's nonce-based script-src)
### Patterns discovered
- webchat.html has ZERO external `<script src>` tags — all functionality is inline IIFE
- `/webchat.html` route overrides Helmet's CSP entirely (res.set replaces header)
- `/chat/:profileId` uses Helmet's global CSP which requires nonce on inline scripts
- `require-sri-for` CSP directive is deprecated (removed from spec, Chrome 96+) — build-time validation is the correct enforcement mechanism
### Gotchas
- The main webchat inline `<script>` at line 745 of webchat.html had no nonce — this was a pre-existing CSP bug for the `/chat/:profileId` route (Helmet requires nonce). Fixed by injecting nonce via regex in the route handler.
