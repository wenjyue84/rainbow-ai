### **Technical Brief: US-537 Kreuzberg Document Extraction Module**

**1. Primary Files to Modify/Create:**
*   `src/lib/kb-extractor.ts`: New TypeScript module to house the extraction logic.
*   `src/lib/__tests__/kb-extractor.test.ts`: New Vitest unit test for the module.
*   (Optional) `scripts/extract_wrapper.py`: A Python script could be created if the `child_process` approach is chosen to wrap the `kreuzberg` CLI, isolating the Python dependency.

**2. Frappe DocTypes / Hooks:**
*   None. This is a standalone Node.js/TypeScript module and does not directly interact with the Frappe framework.

**3. Recommended Implementation Approach:**
*   In `src/lib/kb-extractor.ts`, create the `extractToMarkdown` async function.
*   Use Node's `child_process.spawn` to execute the `kreuzberg` command-line tool, passing the `filePath` as an argument.
*   For image files, add the `--ocr` flag to the `kreuzberg` command based on the function's `opts`.
*   Capture the Markdown output from the process's `stdout` stream.
*   Define a custom `KBExtractorError` class extending `Error` for structured error handling.
*   In the test file, use sample fixtures (e.g., a simple `.txt`, `.docx`, `.png`) to validate that the function returns a non-empty string and handles errors correctly.

**4. Edge Cases & Gotchas:**
*   **Dependency:** `kreuzberg` must be installed and accessible in the system's PATH where the Node.js process runs. OCR may require separate dependencies like Tesseract.
*   **Performance:** Spawning a child process for each file can be slow. If high throughput is needed, a more integrated library or a persistent service might be better.
*   **File Formats:** Markdown conversion quality can vary, especially for complex PDFs or spreadsheets. The output may require further cleaning.
*   **Error Handling:** The `kreuzberg` tool might fail silently or return cryptic errors. The wrapper must reliably catch `stderr` and process exit codes.

## Iteration [1] - Story: Add Kreuzberg Document Extraction Module for KB Ingestion (US-537)

### What was implemented
- Created `src/lib/kb-extractor.ts` module that:
  - Exports `extractToMarkdown(filePath: string, opts?: { ocr?: boolean }): Promise<string>`
  - Uses `child_process.spawn` to call `kreuzberg extract` CLI with `--output-format markdown`
  - Adds `--ocr true` flag when `opts.ocr` is true
  - Captures stdout and returns extracted markdown
  - Throws descriptive `KBExtractorError` for failures

- Created `src/lib/__tests__/kb-extractor.test.ts` with 11 passing tests:
  - Extract from plain text files
  - Clean markdown output validation
  - Error handling for non-existent files
  - OCR option support
  - Empty file detection
  - Special characters in file paths
  - KBExtractorError class validation

### Patterns discovered
- Variable shadowing issue: importing `process` from `process` module while also using child process reference
  - Fixed by renaming child process variable from `process` to `child` to avoid shadowing
- kreuzberg CLI is available in PATH at `/c/Users/Jyue/.local/bin/kreuzberg`
- All tests use temporary directory cleanup with beforeEach/afterEach hooks
- Test fixtures use simple text files to verify extraction returns non-empty markdown

### Gotchas
- Had to use import process from 'process' but then rename the spawn result to avoid shadowing
- kreuzberg returns exit code 0 on success; non-zero codes indicate failure (checked in close event)
- Empty output from kreuzberg is treated as an error (corrupted/unsupported file)
